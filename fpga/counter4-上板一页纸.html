先说清三个词

一捆线：cnt[3:0] 是一个名字带 4 个编号，这 4 根线当一整个数用。
硬件里没有「整捆」这东西，只有一根根线——这词只是我说话方便。

一根线：cnt[1] 就是其中编号 1 的那一根，它只能是 0 或 1。

上升沿：时钟线从 0 跳到 1 的那一瞬间，计数器只在这一下动。

低有效：这根线上的电平是 0 时才触发它的作用（这里是复位）。名字带 _n 的通常就是这个意思。

三句自检（先自己答，再点开）

1. cnt[3:0] 一共几根线？
4 根，编号 0 到 3。方括号里左边是大号。
2. cnt[1] 这一根代表多少？
2。四根的分量分别是 cnt[0]=1、cnt[1]=2、cnt[2]=4、cnt[3]=8。
3. 来一个上升沿，cnt 这个数怎么变？
整个数 +1，不是每根各自 +1。低位从 1 翻回 0 时，才把上一位带动。

它到底在怎么数（看下面跑一轮）

0

0

0

右边数字是「这 16 步里它当了几次 1」。跑满一轮你会看到四个都停在 8——所以四个灯亮的时间完全一样，不存在「有的亮有的暗」。

引脚（这块板，别的地方不通用）

信号脚说明
clkP17板载晶振 50 MHz
rst_nK6按键 PB0，按下是低（低有效：线上是 0 才清零）
cnt[0]K2LED0
cnt[1]J2LED1
cnt[2]J3LED2
cnt[3]H4LED3

你会看到什么

下载完：四个灯常亮。其实每一根都在不停地亮、灭，一亮一灭算一次，每秒 2500 万次——眼睛跟不上，看起来就像一直亮着。 按住 K6：四个灯全灭——因为 rst_n 被拉低，cnt 被清成 0。

松开：立刻恢复常亮，计数器又从 0 往上数。

看不到「在数」是正常的：50 MHz 太快，人眼大约每秒几十次以上就分不出单次闪。想看见数，得先降频——那是下一节课的事。

怎样才算这关过了

灯亮不算过。能用一句话说清这四件事才算：

① 哪个 .v 文件写了这个计数器，哪个 .fdc 把它的信号绑到了脚上
② 约束文件里哪几行把哪几根脚接到了灯上
③ 按 K6 为什么全灭
④ 灯为什么看着常亮、其实在闪

这四句说不清，说明是照着抄的，得退回重问。
